2.ns3相关概念解释&目录解析

ns3版本更迭可以分为几个阶段，

目录结构会随xxx有所变化，按照3.37进行讲解，发生细微改变不会导致主体变化，主要仍内容是一致的。

一、 ns3目录解释

通过bake方法安装ns3之后，有编译结果和测试模块，ns3文件存储在source文件夹下：进入ns3.37文件夹，ns3目录包含文件如下：

AUTHORS        CMakeLists.txt   examples   RELEASE_NOTES.md  testpy.supp
bindings       contrib          LICENSE    scratch           utils
build-support  CONTRIBUTING.md  ns3        src               utils.py
CHANGES.md     doc              README.md  test.py           VERSION

  • scratch 该目录一般存放用户脚本文件，也可以把要运行的例子拷贝到此目录下，该目录是ns-3默认的脚本存放目录，使用waf编译运行脚本文件时，可以不加目录scratch，如果脚本文件在其他目录下需要在文件名前加目录。

  • examples 是由ns-3提供的关于如何使用ns-3的例子，包含了许多模块的使用，如能量、路由、无线网络等，入门ns-3这个目录下例子很重要。其中，tutorial目录下的例子很适合入门者学习。

  • doc 帮助文档，进入tutorial-source，存储的都是适用于不同阶段的手册

    • ns3介绍手册：Introduction

    • 安装手册：Getting Started，介绍了bake，源码安装等几种不同方法安装ns3

    • 编译运行ns3程序：quick-start

  • build ns-3编译结果存放目录，包含编译文件时使用的共享库和头文件

  • src ns-3源代码目录。src下面的子目录：

开始写ns3代码之前，需要先理解一些核心概念和系统的抽象概念，确保为之后打下坚实基础。

二、ns3相关概念

1. 关键概念​

  1. Node 节点

    1. 可以连接到网络的基本计算设备（主机）的抽象。
    2. Node类提供了用于管理计算设备的各种方法。
    3. 对应【Node类】。可以添加功能：应用，协议栈，外围卡和驱动

  2. Application 应用程序

    1. 需要被仿真的用户程序的抽象。（应用程序在节点上运行来驱动模拟过程。）
    2. 不区分系统软件和应用软件，不存在操作系统、优先级、系统调用的概念。
    3. 对应【Application 类】，Application类提供了管理仿真过程中用户层应用的各种方法。
      1. eg：UdpEchoClientApplication和UdpEchoServerApplication。这些应用程序包含了一个client应用和一个server应用来发送和回应仿真网络中的数据包。

  3. channel 信道

    1. 基本的通信子网的抽象。（连接到node）
    2. 建模模拟对象：网线、以太网交换机、无线网络。
    3. 【Channel类】提供了管理通信子网对象和把节点连接至信道的各种方法。
      1. CsmaChannel,PointToPointChannel和WifiChannel。举例来说，CsmaChannel信道模拟了用于一个可以实现载波侦听多路访问的信道，这个信道具有和以太网相似的功能。

  4. Net Device 网络设备

    1. 硬件设备和软件驱动的总和的抽象。
    2. 【NetDevice类】提供了管理node连接其他node和信道对象的各种方法，并且允许开发者以面向对象的方法来自定义。
      1. CsmaNetDevice,PointToPointNetDevice, 和WifiNetDevice。正如以太网卡被设计成在以太网中工作一样，CsmaNetDevice被设计成在csma信道中工作，而PointToPointNetDevice在PointToPoint信道中工作，WifiNetNevice在wifi信道中工作。

  5. Topology Helpers 拓扑帮手

    1. 管理连接：node-net Device-Channel

      1. 创建网络设备，添加mac

      2. 将网络设备安装到node

      3. 配置node协议栈

      4. 将网络设备连接到channel

  6. LOG

  7. trace

三、样例代码解释

examples/tutorial，找到first.cc。实现了点对点通信，发送单个数据包。

::

  #include "ns3/core-module.h"
  #include "ns3/network-module.h"
  #include "ns3/internet-module.h"
  #include "ns3/point-to-point-module.h"
  #include "ns3/applications-module.h"
  
声明引用。ns3后面生成了一个专门的引用文件，查找需要引用的header。在src/core下存放很多header文件。为了避免冲突，编译的时候引用文件专门放在build/ns3文件夹下，公用头文件放在``build/debug`` or ``build/optimized``。

::

  using namespace ns3;
  
命名空间。声明在ns3这个域中。避免命令语句使用ns3::

::

  NS_LOG_COMPONENT_DEFINE ("FirstScriptExample");
  
声明日志组件``FirstScriptExample``，允许启用或关闭组件（控制台消息日志）。

::

    Time::SetResolution (Time::NS);
    
设置分辨率（可以表示的最小时间，两个时间值相差的最小时间），只能修改一次分辨率。默认是1ns。设置占用内存，设置好内存将被释放，无法更新。

::

    LogComponentEnable("UdpEchoClientApplication", LOG_LEVEL_INFO);
    LogComponentEnable("UdpEchoServerApplication", LOG_LEVEL_INFO);
    
启用日志记录组件。适用于echo client，server，在应用的数据包发送和接收的时候打印信息。


【拓扑helper】
NodeContainer
::

    NodeContainer nodes; 
    nodes.Create (2);
 
声明节点容器，创建2个节点。

PointToPointHelper
::

    PointToPointHelper pointToPoint;
    pointToPoint.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
    pointToPoint.SetChannelAttribute ("Delay", StringValue ("2ms"));

实例化一个p2p helper，设置设备属性：传输带宽5Mbps；设置通信channel特性，时延2ms；

NetDeviceContainer
::

    NetDeviceContainer devices;
    devices = pointToPoint.Install (nodes);

声明一个网卡容器设备，利用点对点helper安装节点得出容器设备（设备容器是helper的一个属性）；为每个节点创建点对点网卡设备，二者之间存在一个点对点通信信道。两边设备被配置传输数据带宽5Mbps，信道实验2ms。

InternetStackHelper
::

    InternetStackHelper stack;
    stack.Install (nodes);
    
协议栈设置：InternetStackHelper拓扑帮手中的协议栈帮手；PointToPointHelper点对点网络设备。InternetStackHelper的install方法在nodes容器中的每个节点安装网络协议栈（TCP，UDP，IP）。

Ipv4AddressHelper
::

    Ipv4AddressHelper address;
    address.SetBase ("10.1.1.0", "255.255.255.0");
    
使用管理IP的帮手allocate IP和掩码，声明，IP需要从 10.1.1.0 开始，掩码使用255.255.255.0，默认情况从第一个地址开始，单调增长。如果一个相同IP被生成2次就会引发致命错误。

::

    Ipv4InterfaceContainer interfaces = address.Assign (devices);
    
将IP和device联系起来。

【Applications】
点对点网络连接完毕需要应用生成流量。

UdpEchoServerHelper
::

    UdpEchoServerHelper echoServer (9);

    ApplicationContainer serverApps = echoServer.Install (nodes.Get (1));
    serverApps.Start (Seconds (1.0));
    serverApps.Stop (Seconds (10.0));
    
声明一个UDPEcho服务器helper，帮助我们生成真正的应用，其本身并不是应用。help还可以实现添加特征（eg:设置端口）。install对象是节点容器取参数（隐式转换），生成应用容器，容纳所有helper生成的应用。
应用容器提供开始发送流量，停止发送流量的方法：使用时间作为参数输入。Seconds (1.0)一种C++转换方式，转换为时间。

UdpEchoClientHelper
::

    UdpEchoClientHelper echoClient (interfaces.GetAddress (1), 9);
    echoClient.SetAttribute ("MaxPackets", UintegerValue (1));
    echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
    echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

    ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
    clientApps.Start (Seconds (2.0));
    clientApps.Stop (Seconds (10.0));

对于echo Client，需要5个不同的参数，前两个参数（远端IP地址，远端端口）在UdpEchoClientHelper的构造函数中设置。
Ipv4InterfaceContainer 对象中的第0个接口对应节点容器中的第一个节点的IP。
最大包参数：模拟期间，client允许发送的最大数据包个数。
Interval：数据包之间等待多长时间。
PacketSize：数据包负载多大。
创建Client应用安装到节点0，并告诉其2s开始启动，10s停止发送流量。

【Simulator】
开始模拟

::

    Simulator::Run ();
    
之前调用的这些方法，就是让模拟器在1s，2s，10s的时候执行操作，调度器查找事件调度清单，执行操作，
    
::

    serverApps.Start (Seconds (1.0));
    serverApps.Stop (Seconds (10.0));
    ...
    clientApps.Start (Seconds (2.0));
    clientApps.Stop (Seconds (10.0));
    
::

    Simulator::Destroy ();
    return 0;
  }

执行之后所有剩余的东西都被清理，销毁所有创建的对象。

When the simulator will stop?
模拟器停止的几种方式：
1.事件队列中没有事件，自动停止。
2.使用停止事件：Simulator::Stop (stopTime)。eg：当存在自我维持的事件的时候，导致事件队列一直有事件。
* FlowMonitor - periodic check for lost packets
* RIPng - periodic broadcast of routing tables update
* etc.
* 保持模拟时钟与机器时钟同步，需要先先暂停模拟器。
* 使用停止方法时，必须要先定义Stop，再执行run，避免无法返回控制权给主程序来控制结束。
