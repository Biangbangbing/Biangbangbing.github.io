LeetCode Notebook（1）—— 数据结构【整体框架】

提起数据结构的时候，脑子里浮现的是数组，链表，栈，队列，哈希表，树，图，stl……还总伴随有先进先出，先进后出，底层实现等等话题，单拎起某一个好像都可以头头是道，但是他们相互之间好像又有某种不可名状的关系，简单梳理下多种数据结构之间的关系，来更好地掌握what DT is。

一、数据结构分类

（按照数据间的关系，顺序，一对多还是多对一）​

  1. 线性数据结构：数组、链表、一系列stl容器、栈、队列等等。
  2. 树：二叉树（平衡树，红黑树）、多叉树、b+树、哈夫曼树等等。
  3. 图：单向、无向等等。

二、数据结构分类

（区分逻辑结构和物理结构）​

也就是我们常说的ADT（抽象数据结构）和物理实现结构

  1. 逻辑结构：线性表，栈，队列，STL容器，树等等【这些结构都具有某些增删查改的功能，是封装好的具有某种特性的结构。】
  2. 物理结构：（具体的物理结构有：数组，链表，数组+链表（hash，b+树，这俩其实也可以理解为封装过一次的），邻接矩阵，邻接表……）

如何理解：

ADT的实现都要落实于底层的结构，就是将物理结构封装起来，增添一些增删查改、方便操作的接口。有些ADT甚至不止抽象了一次。

例如：线性表可以用数组也可以用链表实现，树也可以用数组或者链表，图可以用邻接矩阵或者邻接表来实现。一些高级容器的是基于某些逻辑结构实现的，就是高级容器——某些逻辑结构——物理结构。map可以用hash实现也可以用红黑树来实现。（这就是所谓的不止抽象了一次）

三、数据结构基本关系

这部分我会分两个语言来讨论。c++和java，列举常用的（虽然我总是倾向于写能够挖到的全部）容器，他们之间的关系（上面提到的抽象封装的关系），以及他们具体的用法。

C++​

编辑

基础数据结构（物理结构）：构成所有其他带功能的数据结构。（最底层）

容器：带有增删查改功能、某种储存特性的的数据结构。（封装功能）

容器适配器：更高一级的数据结构。（由容器或者其他容器适配器封装）

1.基础数据结构（物理结构）​

名称说明插入/删除（时间复杂度）查询（时间复杂度）适用场景
数组连续地址空间O(n)O(1)频繁查询，但是比较固定，很少或不设计插入、删除元素。
链表非连续节点；包括单向，双向，循环链表等O(1)O(n)频繁插入、删除元素，但是很少查询数据。
邻接矩阵二维矩阵，构成图；点为行列，二维矩阵填写点和点的单向连接关系——————
邻接表所有点为一位数组，每个节点后面跟着的是和这个点连接的节点链表——————

// 数组
int a[100];  // 这种定义方式需要提前知道开辟多大的空间
int a[n];    // 如果只是这样写，因为n是一个变量没办法确定开辟多大的空间(即使你在数组前面赋予了变量值)，有些编译器、oj系统会报错，虽然编译器有些会过，但是不保险，不要使用这种方法。

int a[n] = new int[n];    // 不要写上面那种，写这种非常保险，在堆上new一个大小为n的空间。

delete a;    // 用完之后手动销毁

    int value;
    node* next;
    node() {}
    node(int val) {value:val}
    node(int val, node* next) {value:val, next:next}
}
