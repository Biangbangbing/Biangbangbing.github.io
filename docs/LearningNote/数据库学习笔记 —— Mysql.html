数据库学习笔记 —— Mysql

分析有关数据库的几个关键问题。

学习的数据库：MySQL。

1.数据库发展历史

打孔器——文件系统——数据库（实现数据独立、共享、结构化提高数据控制能力）

2.数据库类型

  1. 网状数据库【有向图】

  2. 层次数据库【树结构组织】

  3. 关系数据库：sql（Structured Query Language）

  4. NoSQL：泛指非关系数据库【解决大规模数据集合和多种数据种类带来的挑战】

    文档型列簇性键值型图形型
    MongoDB，Apache CouchDB，亚马逊AWS的DocumentDBHbase，BigTable，Cloudera，CassandraRedisNeo4j

  5. 分布式数据库

  6. 并行数据库

  7. 多媒体数据库

  8. 云数据库

3.关键概念

  1. 数据：描述事物的符号。
  2. 数据库：长期储存在计算机内、有组织的、可共享的大量数据的集合。
  3. 数据库管理系统【DBMS】：位于用户与操作系统之间的一层数据管理软件，它提供一个可以方便且高效地存取、管理和控制数据库信息的环境。（sql，mysql，H2等等）
  4. 数据库系统：数据库（数据集合）+DBMS+应用+数据库管理员+计算机系统。
  5. 模型：逻辑模型（网状、层次、关系、面向对象）；物理模型（B+树，hash……）
  6. 模式：对数据库逻辑结构和特征的描述，反映数据的结构及其联系，不涉及具体值。
  7. 内模式：数据物理结构和存储方式的描述。记录的存储方式（ 例如，顺序存储，堆存储，按hash方法存储等）；索引的组织方式（B+树，Bitmap，Hash）
  8. 外模式【view】：数据库用户使用的局部数据的逻辑结构和特征的描述，与某一应用有关的数据的逻辑表示。
  9. 二级映像：外模式／模式映像：定义多个外模式与模式之间的对应关系 ；模式／内模式映像：定义数据全局逻辑结构与存储结构之间的对应关系。

4.数据库并发问题【MySQL】

  1. 悲观锁：在操作数据之前将查询到的数据锁住，直到操作完数据之后再释放锁。（利用数据库本身的锁机制和sql语句控制：语句+for update。）（这个分类、底层实现很多，等下细讲）
  2. 乐观锁：设计数据库结构时增加版本控制字段（eg：version，也有的是时间戳），当操作数据之前先取到数据同时取得版本号，操作数据时需要判断刚刚读取的版本号是否 == 这条记录的版本号（取到的是它，在操作的时候还是它），如果相同则操作成功；否则说明数据被别人操作过，本次操作失败。

从大致锁机制上判断可以看到悲观锁不管怎么，先锁再操作；而乐观锁正常操作，不合适就丢弃操作失败。如果总是先锁的话，别的事物就无法操作数据了，这样会造成悲观锁独占资源，程序复杂的时候，开销会很大。
